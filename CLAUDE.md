# CLAUDE.md

+ During your interaction with the user, if you find anything reusable in this project (e.g. version of a library, model name), especially about a fix to a mistake you made or a correction you received, you should take note in the `Lessons` section in the **repo-level** `AGENTS.md` (at the repository root, NOT this global file) so you will not make the same mistake again.
+ Memory is a shared, finite resource. An OOM event can terminate an entire session and its agents, not just the process that exhausted memory. Agent-count limits and per-project locks do not reliably prevent this: processes can have very different memory footprints, and independent projects, sessions, and agents compete for the same machine resources. Enforce machine-wide limits mechanically at launch time, based on process concurrency and memory usage rather than agent count:
  - Run every memory-heavy command through `~/.claude/bin/heavy-gate [-n N] [-m 6G] -- <cmd>`. Claude and OMP share `/tmp/heavy-gate` across all projects, sessions and agents: at most 2 slots, admission only while MemAvailable >= 4500 MiB, and a separate systemd scope with MemoryMax (default 6G) and no swap. If resource isolation is unavailable, refuse execution; never run uncapped. Do not override the shared directory or limits to evade the gate.
  - "Heavy" means every browser launch: Playwright/Puppeteer/Selenium, screenshot/smoke/e2e scripts even with a project gate, Electron, emulators, and any process expected to exceed about 2 GiB. `-n` is the number of browsers the command starts; prefer 1 (`--workers=1`, reuse one context/page).
  - The PreToolUse(Bash) hook (`~/.claude/bin/heavy-gate-hook`) denies recognizable ungated launches, unverified gate paths, a `timeout` wrapper around the gate, and internal checker errors. When denied, rerun under the installed gate; never disguise the command to bypass the hook. Detection is conservative and best-effort, not a sandbox: the rule still applies to dynamic or non-Bash launches it cannot see.
  - The gate waits for capacity rather than failing, sometimes for many minutes. Start finite gated commands with `run_in_background: true`; the foreground Bash timeout is 2 min. Never wrap the gate in `timeout`. `heavy-gate --status` lists holder PIDs, scope names and labels. Slots remain held until all scoped descendants exit, even if the main command has ended or children close inherited descriptors.
  - TERM/INT/HUP stop only that gate invocation's scope. Uncatchable termination such as SIGKILL cannot guarantee cleanup: inspect the scope before assuming its descendants are gone. Stop only holders/scopes you own.
  - When writing code, browser/test launchers must work under the gate: one browser per process, closed in `finally`. Do not add a new per-project lock.
  - When orchestrating (Agent fan-outs, Workflow scripts, /loop, ralph loops), browser work is one 2-wide stage for the whole machine, shared with other sessions. Never put browser verification inside a wide `parallel()`. Run it in batches of ≤ 2 or in one serial verifier agent, and give the other agents static checks and unit tests. Copy the heavy-gate rule into the prompt of every agent that might launch a browser, because subagents can't see each other and may not apply this file. Check `free -m` and `heavy-gate --status` before fanning out.
  - The same applies to any shared, finite resource (ports, GPU, a dev server other agents use). Guard it with a lock or a check at the point of use, never with a headcount rule in a prompt.
  - When modifying this gate or its hook, run the repository's launch-policy regressions with `python3 -m unittest discover -s ~/.claude/tests -p '*_test.py' -v`. Preserve Claude's PreToolUse JSON protocol and `run_in_background` guidance; OMP's extension/Eval APIs and timeout fields are not interchangeable with Claude's.
