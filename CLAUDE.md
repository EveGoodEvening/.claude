# CLAUDE.md

+ During your interaction with the user, if you find anything reusable in this project (e.g. version of a library, model name), especially about a fix to a mistake you made or a correction you received, you should take note in the `Lessons` section in the **repo-level** `AGENTS.md` (at the repository root, NOT this global file) so you will not make the same mistake again.
+ Memory is a shared, finite resource. An OOM event can terminate an entire session and its agents, not just the process that exhausted memory. Agent-count limits and per-project locks do not reliably prevent this: processes can have very different memory footprints, and independent projects, sessions, and agents compete for the same machine resources. Enforce machine-wide limits mechanically at launch time, based on process concurrency and memory usage rather than agent count:
  - Run every memory-heavy command through `~/.claude/bin/heavy-gate [-n N] [-m 6G] -- <cmd>`. It is machine-wide across all projects, sessions and agents: it allows at most 2 slots, starts a command only while MemAvailable ≥ 4.5 GB, and runs each command in its own systemd scope capped at `-m`, so a runaway dies alone. "Heavy" means anything that starts a browser: Playwright/Puppeteer scripts, `playwright test`, and a project's screenshot/smoke/e2e scripts, even when the project has its own gate. It also means Electron, emulators, and any process expected to exceed ~2 GB. `-n` is the number of browsers the command starts; prefer 1 (`--workers=1`, reuse one context/page). A PreToolUse hook (`~/.claude/bin/heavy-gate-hook`) denies ungated Bash commands that start a browser. When it fires, rerun the command under the gate; never reshape the command to get past the hook. The hook can't see every launch, so the rule still applies where it says nothing.
  - The gate waits instead of failing, sometimes for many minutes. Start gated commands with `run_in_background`: the foreground Bash timeout is 2 min, and never wrap them in `timeout`. `heavy-gate --status` lists the holders. A slot that stays busy means an orphan is still running; kill it only if it is yours.
  - When writing code, browser/test launchers must work under the gate: one browser per process, closed in `finally`. Do not add a new per-project lock.
  - When orchestrating (Agent fan-outs, Workflow scripts, /loop, ralph loops), browser work is one 2-wide stage for the whole machine, shared with other sessions. Never put browser verification inside a wide `parallel()`. Run it in batches of ≤ 2 or in one serial verifier agent, and give the other agents static checks and unit tests. Copy the heavy-gate rule into the prompt of every agent that might launch a browser, because subagents can't see each other and may not apply this file. Check `free -m` and `heavy-gate --status` before fanning out.
  - The same applies to any shared, finite resource (ports, GPU, a dev server other agents use). Guard it with a lock or a check at the point of use, never with a headcount rule in a prompt.
